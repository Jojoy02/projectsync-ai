# 安全与隐私

- **密钥**：`FEISHU_APP_SECRET`、`DIFY_APP_API_KEY`、`API_ADMIN_TOKEN` 和事件验证/加密密钥只放在 `.env` 或部署平台 Secret 中。不要提交到 GitHub。
- **身份隔离**：机器人记忆按 `tenant_id + user open_id` 隔离；Dify 的 `user` 字段同样使用租户与用户组合标识。
- **最小权限**：只申请收发机器人消息、读取明确授权文档/日历和编辑映射目标所需的权限。不要为方便而读取整个群聊或整个租户的资料。
- **外部模型处理**：通过 Dify Chatflow 发送给模型的内容包括当前任务相关的工作事实、草稿或文档片段。若使用 Dify 云服务或第三方模型供应商，这些内容会离开本地后端；上线前应由企业确认数据分类、模型服务条款和部署方式。敏感工作资料建议使用企业批准的私有化/受控 Dify 与模型环境。
- **数据库**：SQLite 中包含个人工作事实、草稿、来源链接和审计记录。限制服务器文件访问，配置备份和保留期限；不要把 `data/` 上传到公开仓库。
- **回调安全**：配置飞书 Verification Token；生产环境必须配置公网 HTTPS。若启用事件加密，设置 `FEISHU_ENCRYPT_KEY`。
- **写回保护**：默认关闭写回。开启后仍要求用户确认、目标块映射、生成时快照和写入前比较。目标发生变化时停止，不自动覆盖。
- **消息幂等**：通过 `message_id` 去重，避免飞书重试导致重复执行。
- **日志**：应用日志不主动记录原始工作正文或密钥；部署平台仍需控制日志访问权限。
- **管理 API**：`/api/targets`、`/api/docs/blocks`、`/api/ingest`、`/api/facts` 和调度测试接口需要 `X-Admin-Token`。应在 HTTPS 下使用，并限制管理接口的网络可达范围。
